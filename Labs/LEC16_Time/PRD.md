# 10마리 새떼 비행 애니메이션 PRD

## 1. 문서 목적

`bird_animation.png` 스프라이트를 활용해 화면에 10마리의 새를 표시하고, 새떼가
좌우 방향으로 반복 비행하는 애니메이션을 구현하기 위한 개발 문서다. 애니메이션은
프레임 시간 기반으로 갱신하여 프레임률이 달라도 이동 속도와 날갯짓 속도가 일정하게
보이도록 한다.

## 2. 대상 파일과 리소스

- `bird_animation.png`: 새의 날갯짓 프레임을 포함한 스프라이트 이미지
- `play_mode.py`: 새떼 객체 생성 및 게임 월드 등록
- `game_world.py`: 새떼의 업데이트와 렌더링 호출
- `game_framework.py`: 한 프레임의 경과 시간(`frame_time`) 제공
- `PRD.md`: 본 기능의 요구사항과 구현 논리

## 3. 기능 요구사항

1. 게임 시작 시 새 객체를 정확히 10마리 생성한다.
2. 10마리 모두 `bird_animation.png`를 사용해 날갯짓 애니메이션을 출력한다.
3. 새떼는 화면의 좌우 경계 사이를 수평으로 비행한다.
4. 선두 새가 오른쪽 경계에 도달하면 진행 방향을 왼쪽으로 바꾸고, 왼쪽 경계에
   도달하면 진행 방향을 오른쪽으로 바꾼다.
5. 방향 전환 시 새 이미지도 진행 방향에 맞게 좌우 반전한다.
6. 선두 새는 목표 방향으로 부드럽게 회전하고, 나머지 새는 선두와 앞 새의
   궤적을 일정한 간격으로 추종한다.
7. 새마다 시작 위치와 날갯짓 프레임의 시작값을 다르게 하여 10마리가 겹쳐 보이지
   않고 자연스러운 새떼처럼 보이게 한다.
8. 새의 수는 항상 10마리로 유지하며, 비행 중 임의로 생성하거나 제거하지 않는다.
9. 새의 이동과 애니메이션은 `game_framework.frame_time`을 사용해 시간 기반으로
   처리한다.

## 4. 애니메이션 및 이동 논리

### 4.1 스프라이트 프레임

- `bird_animation.png`의 각 날갯짓 셀을 동일한 크기의 직사각형으로 잘라 사용한다.
- 현재 프레임은 `frame = (frame + FPS * frame_time) % frame_count` 방식으로
  증가시킨다.
- 실제 렌더링 시에는 현재 프레임을 정수로 변환해 해당 셀만 그린다.
- 프레임 인덱스는 위치와 독립적으로 관리하여 이동 방향이 바뀌어도 날갯짓이
  끊기지 않게 한다.

### 4.2 수평 왕복

- 선두 새는 `x += velocity_x * frame_time`으로 위치를 갱신하며, 목표 방향을
  향하도록 `velocity_x`를 가속한다.
- `direction`은 오른쪽 진행 시 `1`, 왼쪽 진행 시 `-1`로 관리한다.
- 새의 중심이 화면 밖으로 나가지 않도록 새의 반쪽 너비를 고려한 경계를 사용한다.
- 선두의 `x >= right_bound`이면 목표 방향을 `-1`, `x <= left_bound`이면
  목표 방향을 `1`로 변경한다.
- 방향 전환은 목표 방향만 먼저 변경하고 실제 속도는 `TURN_ACCELERATION`으로
  점진적으로 감속·가속하여 철새의 완만한 선회처럼 보이게 한다.

### 4.3 철새형 선두-추종 비행

- 선두 새는 새떼의 진행 방향과 경계 반전을 결정한다.
- 최근 선두 위치를 `trail`에 시간 순서로 저장한다.
- 각 추종 새는 `FOLLOW_DELAY * index`만큼 늦은 trail 위치를 목표로 삼아
  `position += (target - position) * FOLLOW_STEERING * frame_time`으로 접근한다.
- 추종 새의 목표 위치에는 `FORMATION_GAP`과 행별 세로 오프셋을 적용한다.
  따라서 새떼는 선두의 경로를 따르면서도 한 줄로 겹치지 않는다.
- 목표 위치에 가까워질수록 추종 속도가 자연스럽게 줄어들도록 최대 속도를 제한한다.
- 선두와 추종 새 모두 같은 `direction`을 공유하여 이동 방향과 스프라이트
  좌우 반전이 일관되게 유지된다.

### 4.4 10마리 배치

- 새 객체는 하나의 공통 클래스와 개별 상태값(`x`, `y`, `direction`, `frame`)을
  갖는다.
- 생성 시 화면 안에 10개의 서로 다른 좌표를 지정한다.
- 선두 1마리와 추종 9마리를 생성한다.
- `y` 좌표는 행을 나누어 배치하고, `x` 좌표는 선두와의 간격 및 작은 오프셋을
  조합해 새들이 완전히 포개지지 않도록 한다.
- 각 새의 `frame` 시작값은 `index % frame_count`로 분산한다.
- 추종 새는 선두의 이동 궤적을 공유하므로 개체별 속도 차이보다 대형 유지가
  우선된다.

## 5. 상태 및 생명주기

| 상태       | 진입 조건    | 업데이트                          | 종료 조건                     |
| ---------- | ------------ | --------------------------------- | ----------------------------- |
| `FLYING` | 새떼 객체 생성 | 프레임 증가, 선두 이동, 추종 조향, 경계 반전 | 게임 월드 종료 또는 객체 제거 |

- 새는 별도의 입력 없이 `FLYING` 상태를 유지한다.
- `play_mode.init()`에서 하나의 새떼 객체를 생성하고, 새떼 내부에서 정확히
  10마리를 생성한다.
- `play_mode.finish()` 또는 게임 월드 정리 시 새 객체를 함께 정리한다.
- 업데이트와 렌더링은 게임 월드의 기존 순서를 따르며, 새 객체가 직접 게임 루프를
  호출하지 않도록 한다.

## 6. 렌더링 규칙

1. 현재 프레임의 스프라이트 셀을 새의 중심 좌표에 출력한다.
2. 오른쪽을 향할 때는 원본 셀을 출력하고, 왼쪽을 향할 때는 수평 반전(`h`)한다.
3. 모든 새가 같은 위치에 그려지지 않도록 배치 좌표를 개별적으로 사용한다.
4. 새의 충돌 판정은 본 기능의 범위에 포함하지 않는다.

## 7. 검증 기준

- 실행 직후 화면에 새가 정확히 10마리 보인다.
- 모든 새가 `bird_animation.png`의 날갯짓 프레임을 순환한다.
- 새떼가 왼쪽과 오른쪽 경계를 반복해서 왕복하며 화면 밖으로 사라지지 않는다.
- 방향 전환 시 이미지가 진행 방향에 맞게 반전된다.
- 프레임률을 변경해도 실제 이동량이 경과 시간에 비례하고 애니메이션 속도가
  과도하게 빨라지거나 느려지지 않는다.
- 새들의 시작 위치와 프레임이 분산되어 하나의 이미지처럼 겹쳐 보이지 않는다.
- 선두가 방향을 바꿀 때 추종 새들이 지연된 궤적을 따라가며 대형을 유지한다.
- 모드 종료 후 새 객체가 게임 월드에 남지 않는다.

## 8. 최종 커밋 로그 기록

최종 커밋 로그에는 새의 정확한 비행 애니메이션을 위해 적용한 개발 논리를
명시한다. 기록 내용에는 `frame_time` 기반 시간 보정, 스프라이트 프레임 순환,
10마리의 위치·프레임 분산, 선두의 경계 반전, 추종 새의 지연 궤적 조향,
이동 방향에 따른 이미지 좌우 반전이 포함되어야 한다. 이를 통해 단순히 결과물만
남기는 것이 아니라 철새형 새떼 움직임이 정확하게 구현된 근거와 설계 의도를
커밋 이력에서 확인할 수 있도록 한다.
